| 项目 | 内容 |

本 PRD 的检索范围由 W2 真实实验锁定。它不继承论文第五章的模拟指标，也不把合成数据结果表述为生产效果。

## 1. 问题背景与机会决策

### 1.1 用户问题

测试知识分析员需要从分散的文本、PDF、图片说明和测试记录中找出与当前问题相似的历史场景，复核触发条件、系统响应和原始证据。现有流程通常依赖文件名、标签、关键词和个人经验；当用户使用同义表达或组合多个条件时，相关记录可能被漏掉。

当前问题的业务强度尚未通过真实用户访谈确认。W3 必须完成 5 次访谈，并记录检索耗时、返工和证据复核方式；若至少 3 名用户不能提供可量化损失，本项目停止扩展。

### 1.2 技术机会证据

W2 在 40 个脱敏合成场景和 36 条冻结黄金查询上比较四组方案。结构化场景单元 Dense（C 组）相对普通文档块 Dense（B 组）：Recall@5 同为 100%，nDCG@5 从 0.9752 提升至 0.9978；相对 BM25，同义改写查询的召回改善明显。

Dense + Sparse（D 组）没有超过 C：nDCG@5 下降 1.22 个百分点，无答案误召回率从 12.50% 上升至 50.00%。因此 MVP 采用更简单、证据更强的 C 组链路。

### 1.3 产品定位

产品把脱敏资料组织为统一场景单元，接受自然语言问题，返回 Top 5 相似场景、匹配条件、来源证据和复核入口。它是“场景检索与证据复核工具”，不是通用企业聊天机器人，也不替用户作最终安全判断。

## 2. 用户、JTBD 与当前工作流

### 2.1 用户角色

| 角色 | 核心任务 | 产品权限 |
|---|---|---|
| 测试知识分析员（首要） | 查找相似场景、比较差异、定位证据 | 导入脱敏资料、检索、提交反馈 |
| 测试负责人（次要） | 复核检索结果与失败案例 | 查看场景、证据和评估摘要 |
| 产品经理/领域专家（次要） | 判断场景覆盖与产品风险 | 查看结果、标记证据不足 |

MVP 为单用户本地演示，不实现生产身份、角色和数据隔离。上述角色用于定义任务，不代表已完成权限系统。

### 2.2 JTBD

当分析员需要验证一个复杂测试问题时，希望用自然语言描述天气、道路、参与者、触发事件和系统表现，在 3 分钟内获得最相关的历史场景与可定位证据，从而减少跨文件查找和人工拼接。

### 2.3 当前工作流

1. 在多个目录中按文件名或标签搜索；
2. 打开多个候选文件，人工确认上下文；
3. 复制天气、对象、触发事件和响应信息；
4. 回到原文件确认来源；
5. 将结论写入测试记录。

W3 需要测量第 1–4 步的人工基线时间。未得到基线前，PRD 不承诺“节省 50% 时间”。

## 3. 用户旅程与关键场景

### 3.1 正常旅程：复合条件检索

1. 分析员导入一组已经脱敏的场景资料；
2. 系统显示导入数量、成功数量和解析失败项；
3. 分析员输入“雨夜路口行人从停放车辆后突然出现”；
4. 系统返回 5 张场景卡片，第一张展示环境、参与者、触发事件、系统响应和匹配原因；
5. 分析员展开证据，跳转到具体文件与片段；
6. 分析员标记“相关”，并把结果加入复核清单。

### 3.2 异常旅程：证据不足

1. 分析员查询语料库中不存在的条件组合；
2. 系统仍执行检索，但不得把相似分数直接表述为事实置信度；
3. 若规则校验发现关键字段无匹配，页面提示“未找到满足全部条件的场景”，同时把候选结果标记为“仅供扩展搜索”；
4. 分析员可以修改查询或标记“无答案”；
5. 自动阈值拒答在 P1 验证完成前不得取代规则校验和人工判断。

### 3.3 异常旅程：模型不可用

若百炼接口超时或失败，系统回退至 BM25，页面明确展示“语义检索暂不可用，当前为关键词结果”。不得静默切换后继续显示语义分数。

## 4. 场景单元的数据结构与来源

### 4.1 P0 Schema

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| `scene_id` | string | 是 | 稳定唯一，不因重新索引改变 |
| `title` | string | 是 | 简短标题，不包含敏感主体 |
| `summary` | string | 是 | 场景自然语言摘要 |
| `environment` | object | 是 | 天气、光照、道路、路面 |
| `actors` | string[] | 是 | 自车与关键参与者 |
| `trigger` | string | 是 | 触发事件 |
| `system_behavior` | string | 是 | 系统实际响应 |
| `expected_behavior` | string | 是 | 期望行为或测试关注点 |
| `risk` | string | 是 | 待复核风险，不作最终结论 |
| `evidence` | Evidence[] | 是 | 来源、片段位置和摘要 |
| `tags` | string[] | 否 | 筛选辅助，不作为黄金答案 |
| `synthetic` | boolean | 是 | 演示数据固定为 `true` |
| `source_basis` | string | 是 | 演示数据固定为 `method-only` |

`Evidence` 至少包含 `source_id`、`source_type`、`locator`、`excerpt`。MVP 支持 Markdown/TXT、可提取文本的 PDF 和 CSV 元数据；图片只允许作为证据附件展示，不在 v1 建立图片向量。

### 4.2 数据来源边界

- 公开演示只使用合成或已获授权的脱敏资料；
- 不上传车牌、VIN、人员信息、真实轨迹和内部系统地址；
- 导入前进行文件级确认，解析后进行字段级预览；
- 不把 MBA 论文正文当作产品语料，只复用方法框架。

## 5. 导入、抽取、检索、回答与反馈功能

### 5.1 功能优先级

| 编号 | 功能 | 优先级 | W2 证据影响 |
|---|---|---|---|
| FR-01 | 导入脱敏资料并保留来源 | P0 | 端到端闭环入口 |
| FR-02 | 抽取、预览并修正场景单元 | P0 | C 相对 B 的 nDCG@5 +2.26 pp |
| FR-03 | 自然语言查询与字段筛选 | P0 | Dense 在同义改写上优于 BM25 |
| FR-04 | 返回 Top 5、匹配原因与证据 | P0 | C 组 Recall@5=100% |
| FR-05 | 引用回答、规则校验与人工拒答 | P0 | 自动阈值尚不稳定 |
| FR-06 | 相关性、引用错误和补充说明反馈 | P0 | 支撑盲测和后续评估 |
| FR-07 | 运行黄金集并展示指标 | P0 | 已有可复现实验管线 |
| FR-08 | 记录时延、Token 和成本 | P1 | W2 已验证记录口径 |
| Dense + Sparse | P1 | P1 | D 未超过 C，误召回率 50% |
| 自动阈值拒答 | P1（待验证） | P1 | 仅 8 条开发查询，外部效度不足 |

### 5.2 FR-01 导入

**输入：** 用户选择最多 50 个文件；单文件不超过 10 MB；格式为 `.md`、`.txt`、文本型 `.pdf` 或 `.csv`。

**处理：** 系统计算文件哈希、抽取文本、记录来源 ID，并在提交前显示脱敏确认。完全重复文件只索引一次，同时保留来源列表。

**输出：** 成功数、失败数、跳过数和逐文件状态。

**异常：** 加密 PDF、扫描 PDF、空文件、超限文件或无法解析编码进入失败列表，不阻塞其他文件。

### 5.3 FR-02 场景抽取与修正

**输入：** 已解析文本与来源定位。

**处理：** 系统生成 P0 Schema；缺失字段标记为“需复核”，不得编造。用户可以修改字段后确认入库。

**输出：** 场景卡片、来源证据和字段完整状态。

**异常：** 同一来源抽取出多个场景时分别编号；无法识别触发事件时不进入可检索状态。

### 5.4 FR-03/FR-04 查询与结果

**输入：** 2–200 字自然语言查询，可选天气、光照、道路和参与者筛选。

**处理：** 按固定字段顺序序列化场景单元，调用 `text-embedding-v4` 生成 1024 维 Dense 查询向量，对当前 MVP 库做余弦排序。筛选条件先过滤候选，再计算 Top 5。

**输出：** Top 5 场景、相似分数、满足/不满足条件、关键差异和证据入口。相似分数只能命名为“检索相似度”，不能命名为“正确率”或“安全置信度”。

**异常：** 百炼不可用时回退 BM25；没有候选时返回空状态；所有候选缺少关键条件时显示证据不足提示。

### 5.5 FR-05/FR-06 引用、拒答与反馈

引用回答只能重述已显示的场景字段，并在每个关键结论后附 `source_id + locator`。若证据缺失，回答必须删除对应判断或标记“不确定”。用户可提交：相关、不相关、引用错误、补充说明、无答案。

自动阈值拒答 | P1（待验证）。v1 的 P0 拒答只基于明确规则：空候选、关键筛选条件无匹配、来源不可访问或用户主动判定无答案。

## 6. AI 技术链路与基线

### 6.1 已锁定链路

```text
脱敏文件
  → 文本解析与来源定位
  → 场景 Schema 抽取/人工确认
  → 固定字段序列化
  → text-embedding-v4 Dense 1024 维
  → 余弦相似度 Top 5
  → 条件差异与来源证据
  → 用户反馈
```

### 6.2 选型记录

| 方案 | 产品状态 | 原因 |
|---|---|---|
| BM25 | 降级与对照 | 本地快速、精确术语强；同义改写弱 |
| 原始文档块 Dense | 不选 | 排序质量低于结构化场景单元 |
| 结构化场景单元 + Dense | MVP P0 | Recall@1 100%，nDCG@5 0.9978 |
| 结构化场景单元 + Dense+Sparse | P1 | nDCG 下降，拒答误召回恶化 |
| rerank | 非 v1 | 尚无证据证明需要，避免增加成本和变量 |

### 6.3 模型调用

- 模型：阿里云百炼 `text-embedding-v4`；
- 区域：中国内地公开端点；
- 维度：1024；
- 单批上限：10 条；
- Key：只从 `DASHSCOPE_API_KEY` 读取；
- 缓存：模型、维度、输出类型和文本 SHA-256；
- 重试：仅 429/500/502/503/504，最多 3 次；
- 降级：调用失败后使用 BM25，并向用户展示降级状态。

## 7. 黄金集、离线评估与人工评审

### 7.1 W2 已测基线

| 指标 | 结构化场景 Dense 实测 |
|---|---:|
| Recall@1 | 100.00% |
| Recall@5 | 100.00% |
| MRR | 1.0000 |
| nDCG@5 | 0.9978 |
| 无答案误召回率 | 12.50% |
| P50 端到端时延 | 405.27 ms |
| P95 端到端时延 | 632.55 ms |

上述数值来自合成语料，不是发布承诺。进入 W4 原型前，必须新增至少 20 条来自 W3 用户原话的盲测查询；它们不能参与字段模板、权重或阈值调整。

### 7.2 MVP 验收目标

| 指标 | 验收目标 | 数据集 |
|---|---:|---|
| Recall@5 | ≥ 80% | W2 黄金集 + W3 盲测集 |
| 引用准确率 | ≥ 90% | 人工逐条确认引用是否支持结论 |
| 无依据回答率 | ≤ 10% | 证据不足问题的人工评审 |
| P95 检索时延 | ≤ 1 秒 | 缓存预热后的远程 API 测试 |
| 可追溯覆盖率 | 100% | 每个结果有来源或明确无答案 |

### 7.3 评估治理

开发集只用于模型和阈值选择；黄金集与盲测集不得逐题调参。任何数据或标签修改都要更新 SHA-256、记录原因并重跑全部方案。报告同时保留失败样例，不只展示平均分。

## 8. 引用、拒答、隐私与人工接管

### 8.1 信任规则

1. 检索相似度不等于事实正确率；
2. 生成结论必须回到来源片段；
3. 来源不可访问时不展示该证据内容；
4. 关键条件不满足时必须展示差异；
5. 用户拥有最终采纳、纠错和拒绝权。

### 8.2 隐私规则

- 公开演示禁止真实涉密数据；
- 日志不保存 API Key、完整文件正文或个人身份信息；
- 缓存只保存合成/已授权文本的向量；
- 删除场景时同步删除文本、向量与证据定位；
- v1 不实现生产权限系统，因此不得接入真实企业知识库。

### 8.3 人工接管

以下情况必须人工确认：场景字段缺失、关键条件冲突、来源不可访问、自动拒答不确定、结果用于安全或合规判断。界面提供“加入复核清单”，而不是“自动批准”。

## 9. 时延、稳定性与成本要求

| 项目 | v1 要求 | 测量方法 |
|---|---:|---|
| P95 查询端到端时延 | ≤ 1 秒 | 预热后至少 30 次查询 |
| P95 本地排序时延 | ≤ 50 ms | 40–500 场景精确排序 |
| API 失败降级 | 100% 显示降级状态 | 注入 429、5xx、网络错误 |
| 数据与结果一致性 | 同一输入与版本排名稳定 | 固定哈希重复运行 |
| 单查询 Embedding 费用 | 记录实际值，目标 ≤ 0.001 元 | API Token × 当日单价 |

W2 完整实验实际使用 11,043 Token、100 次请求，按 2026-07-12 官方原价估算 0.005522 元。该费用包含三套语料索引和两种查询向量，不等同于生产单查询成本。

## 10. 埋点与成功指标

### 10.1 事件

| 事件 | 触发 | 必填字段 | 目的 |
|---|---|---|---|
| `source_imported` | 文件解析完成 | source_type, status, scene_count, latency_ms | 导入质量 |
| `scene_confirmed` | 用户确认场景单元 | scene_id, corrected_fields | 抽取修正率 |
| `search_submitted` | 提交查询 | query_id, query_length, filters, retrieval_mode | 查询构成 |
| `search_results_shown` | Top 5 展示 | query_id, latency_ms, result_count, degraded | 体验与降级 |
| `evidence_opened` | 打开证据 | query_id, scene_id, rank, source_id | 可追溯使用率 |
| `result_feedback` | 提交反馈 | query_id, scene_id, rank, feedback_type | 在线质量 |
| `search_abstained` | 规则拒答 | query_id, reason | 拒答有效性 |

日志中的查询正文默认不进入分析事件，只保存长度、筛选条件和匿名 ID；调试样本需用户单独确认。

### 10.2 产品成功指标

北极星指标为“完成证据复核的有效查询数”，定义为用户打开至少一个来源并提交相关/不相关反馈的查询。W3 未完成前不设活跃用户和商业转化目标。

### 11.2 三分钟演示

## 12. 风险、开放问题与后续路线

### 12.1 风险

| 风险 | 当前证据 | 缓解方式 |
|---|---|---|
| 合成数据高估效果 | C 组接近满分 | W3 用户原话盲测，不参与调参 |
| 自动拒答不稳定 | C 组黄金误召回 12.50%，D 为 50% | v1 使用规则拒答和人工接管 |
| 场景抽取产生幻觉 | W2 使用人工构造 Schema，未测自动抽取 | 缺失字段不补写，入库前人工确认 |
| API 网络与供应商依赖 | W2 P95 632.55 ms | 缓存、有限重试和 BM25 降级 |
| 敏感数据外发 | v1 需调用外部 Embedding API | 仅合成/授权数据；生产接入另行安全评审 |
| “多模态”名不副实 | 本轮只验证文本 | W3 证明图片任务后再建独立消融实验 |

### 12.2 W3 必须回答的问题

1. 用户最常用的查询语言是关键词、同义表达还是复合条件？
2. 当前一次检索与复核实际耗时多少？
3. 哪些任务必须查看图片才能作出判断？
4. 用户是否愿意为可追溯证据接受约 0.4–0.7 秒等待？
5. 无答案时，用户更信任规则提示、相似候选还是人工复核？

### 12.3 范围变更规则

新增功能必须直接改善一个已定义指标，或替换同等工作量的现有功能。图片向量、Dense+Sparse、rerank、生产 RBAC、企业连接器、多租户、计费和自动执行全部进入后续路线，不得追加到 v1。
