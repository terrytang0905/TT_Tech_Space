# 企业级多模态场景知识 Agent MVP

## 一句话说明

把分散的脱敏测试资料整理为结构化场景单元，用自然语言检索相似场景，并返回可复核证据。这个项目不是通用聊天机器人，而是面向测试知识分析员的“场景检索与证据复核”原型。

## 背景问题

测试知识分析员经常需要从历史记录中寻找相似场景：天气、光照、道路、参与者、触发事件和系统响应都可能影响判断。传统关键词搜索在同义表达和复合条件下容易漏召回，人工跨文件核对也难以稳定复现。

本 MVP 先把问题压缩到一个可验证边界：40 个合成智驾测试场景、8 条开发查询、36 条冻结黄金查询。所有数据只用于产品方向判断，不构成真实道路安全结论。

## 产品目标

- 让用户用自然语言描述复杂场景，获得 Top 5 相似历史场景。
- 返回匹配条件、关键差异和来源证据，而不是只给一个答案。
- 保留人工复核入口，避免把检索相似度误表述为事实置信度。
- 用可复现实验决定 MVP 检索链路，而不是凭直觉选型。

## 实验设计

| 组别 | 数据表示 | 检索方式 | 目的 |
|---|---|---|---|
| A | 原始文档块 | BM25 | 关键词基线 |
| B | 原始文档块 | Dense | 验证语义检索收益 |
| C | 结构化场景单元 | Dense | 验证 Schema 化表达收益 |
| D | 结构化场景单元 | Dense + Sparse | 验证混合检索是否继续提升 |

评估指标包括 Recall@1、Recall@5、MRR、nDCG@5、无答案误召回率、P50/P95 时延和 API 成本。

## 关键结果

| 组别 | Recall@1 | Recall@5 | MRR | nDCG@5 | 无答案误召回率 |
|---|---:|---:|---:|---:|---:|
| A BM25 | 85.71% | 96.43% | 0.9018 | 0.9187 | 0.00% |
| B 原始块 Dense | 92.86% | 100.00% | 0.9643 | 0.9752 | 12.50% |
| C 场景单元 Dense | 100.00% | 100.00% | 1.0000 | 0.9978 | 12.50% |
| D 场景单元混合 | 96.43% | 100.00% | 0.9821 | 0.9856 | 50.00% |

结构化场景单元 Dense 是本轮最稳健方案：相对原始块 Dense，Recall@5 持平，nDCG@5 提升 2.26 个百分点。Dense + Sparse 没有继续提升排序质量，并把无答案误召回率推高到 50.00%。

## 产品决策

- P0：保留场景 Schema 抽取、字段预览和人工修正。
- P0：采用结构化场景单元 + `text-embedding-v4` Dense 1024 维检索。
- P0：返回 Top 5 场景、条件差异和证据入口。
- P1：Dense + Sparse 混合检索继续作为实验项，不进入首个演示闭环。
- P1：自动阈值拒答继续验证；MVP 只采用规则校验和人工复核。

## 作品集讲述重点

这份作品集可以按“问题 - 证据 - 决策 - 原型”的顺序讲述：

- 问题：关键词搜索难以覆盖同义表达和复合条件，人工复核过程不可稳定复现。
- 证据：用冻结黄金集比较四组检索链路，并记录召回、排序、无答案误召回、时延和成本。
- 决策：选择结构化场景单元 Dense 作为 P0，把混合检索和自动阈值拒答延后验证。
- 原型：用静态页面展示查询、指标对比、Top 5 场景、证据片段和人工复核入口。

## 可复现方式

从仓库根目录运行：

```bash
make check
```

该命令会执行离线单元测试、冻结数据检查和已有实验产物复核。真实百炼 API 集成测试默认跳过，避免在普通验证中产生调用费用。
